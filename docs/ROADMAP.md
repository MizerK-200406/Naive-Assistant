# RAG-first roadmap

The initial milestone targets a single Vietnamese history lecture PDF, local inference, and CLI evaluation. It precedes Phase 1 and does not satisfy the full Phase 2 web-upload acceptance criteria.

### Current verification, 2026-11-19

- **M0–M2.** The Python CLI and its configured checks run locally. Re-extraction of
  the 169-page PDF and regeneration of 657 chunks reproduced the reviewed corpus.
  All chunks map to one retained fragment and carry correct source/page metadata.
  Visual checks confirmed internal word-spacing and wrapped-heading defects. There
  are 352 within-fragment boundaries at the 160-unit cap without sentence-ending
  punctuation. Diagram-only evidence remains unavailable. The local audit is
  `backend/.local/m1-m2-audit.md`.
- **M3.** All four combinations of MiniLM/MPNet and top-k 4/8 were compared on 40
  dev queries. MPNet top-4 hit a labelled page for 35/35 answerable questions
  (mean coverage 0.8008, MRR 0.8857). MiniLM top-8 reached 35/35 and 0.8854
  coverage with roughly 1,026 more mean input tokens on the validation-retry path.
  The newly built, snapshot-bound MPNet index reproduced all 40 legacy top-4
  rankings. Vector points were present on 166/166 content pages. Ranked searches
  using a source-text sample from each page recovered 134/166 at top-4.
- **M4–M5.** The `eval-batch` development CLI runs retrieval in a short-lived
  process before generation. It writes per-question retrieval, citations, refusal
  or failure and checks the local Ollama digest before and after generation.
  Six cross-exclusion expansions were eliminated in an offline experiment.
  All guarded contexts fit the model window, but the four paired live diagnostics
  did not support adopting neighbor expansion. A stricter sufficiency instruction
  rejected all three previously reviewed positive contexts out of eight probes.
  It was kept experimental. See the root handoff for batch results and M6–M7 gates.

### Earlier milestone history

- M0: Python 3.12 package, CLI, dependency and quality-tool configuration. Verified with CLI help, pytest and Ruff; application runtime configuration remains for the first feature that needs it.
- M1 (layout review complete; extraction quality still in progress): All 169 PDF pages were visually inspected for layout, and the hash-bound review artifact covers every page. Front matter and diagram text whose spatial relationships are lost are excluded. The diagrams on PDF pages 14, 22, 75, 86, 122, 130, 140 and 148 are images absent from extracted text; their contents are unavailable as evidence without OCR or transcription. This was a layout and diagram review, not a word-by-word transcription audit. Internal word spaces, duplicate PDF dictionary warnings, and broader extraction quality remain unresolved. The full review artifact is `backend/.local/review-pages-1-169.json` and remains local/ignored.
- M2 (prototype): A full-document diagnostic produced 657 chunks from 166 pages; pages 1–3 are excluded front matter. Per-page whitespace-normalized output matches the reviewed fragments, including exclusions. Bare footnote numbers no longer become headings. A conservative heuristic joins some wrapped heading lines; other wrapped headings remain incomplete and the heuristic can misclassify text. The bibliography marker resets the heading path and suppresses numbered-entry headings across pages. Overlap, cross-page context, chunk boundary quality and source-level validation remain unfinished. This diagnostic is not an index or a retrieval evaluation.
- M3 (prototype): BM25, rank fusion, and a Qdrant Local vector store with an injectable embedder have synthetic tests. A CPU FastEmbed adapter produced a 384-dimensional vector offline using multilingual MiniLM, and rejects inputs at the model token limit rather than silently truncating. Long inputs are split into token-guarded windows, vector hits are deduplicated by chunk using maximum score, and BM25/RRF hybrid retrieval passed a small offline synthetic smoke test. Disk persistence has a manifest, corpus hash, completion marker and vector payload checks; a synthetic offline reopen/search smoke test passed. Failed creation leaves an incomplete directory requiring a new output path. Model identity currently uses name/dimension, not artifact digest. Performance, comparison against MPNet and document evaluation remain.

  A subsequent T002 trace verified source PDF identity and exact layout extraction for PDF page 10. All six indexed chunks on that page match its reviewed text and retain the three function headings. The fixed MiniLM/candidate-20/RRF-60/top-k-4 pipeline instead retrieves pages 9, 4, 11 and 8: related material, tasks, or a heading, not the requested function list. The education, cognition and forecasting/criticism chunks rank 6, 10 and 19 in fusion; top-k 8 still lacks the complete list. - M4 (prototype): development uses `backend/eval/datasets/test.yaml`, schema 2.0, `split: test`, 40 questions (35 answerable, five unanswerable); the reserved holdout contains 10 questions. Schema compatibility covers safe YAML, source hashes, recorded PDF/printed page labels, split isolation, counts and evaluation metadata. Dev-only retrieval provides page metrics and optional reviewed evidence-group coverage; metrics are not applicable (`null`) for unanswerable questions. Single-question capture stores retrieved chunks, citations or error stage, dataset/index hashes and a code hash without passing evaluator labels to the answering model. The unchanged draft A–E scorer accepts answerable questions only; scoring rules for unanswerable questions require separate owner approval. Model artifact digests, batch capture, evidence-span labels, human scoring, aggregate reporting, approved thresholds and final frozen holdout workflow remain unfinished. Compatibility checks are not a 40-question quality evaluation. No retrieval or model runs have been performed on the holdout.
